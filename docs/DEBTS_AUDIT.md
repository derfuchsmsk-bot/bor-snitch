# Аудит долгов

## Найденные ошибки

- Комментарии, дневной анализ и проверка договорённостей независимо прибавляли одни и те же операции. Повторный запуск анализа снова менял остаток.
- `merge=True` рекурсивно объединял вложенные карты Firestore: удаление пары из Python-словаря не удаляло её из базы.
- Автоматические обработчики по-разному определяли участников, а сопоставление по части имени могло выбрать другого человека.
- Нулевое или отрицательное частичное погашение в API превращалось в полное списание. Дробные суммы могли округляться.
- Бот объявлял записанными все предложения AI, даже пропущенные или повторные операции.
- Повторный клик и повтор запроса после потери ответа могли дважды прибавить долг или списать возврат.
- Имена вставлялись в inline JavaScript: апостроф ломал кнопки и создавал возможность исполнения кода.
- Обнаруженный позднее долг мог примениться после возврата и оставить неверный остаток.

## Устройство исправления

`DebtService` проверяет исходный Telegram MsgID, участников и суммы для всех трёх автоматических обработчиков. Контекст, будущие сообщения и сообщения бота не являются источниками для текущего комментария. Имена сопоставляются по точным уникальным username, именам и явно заданным псевдонимам лора; неоднозначные и неизвестные участники в автоматическом разборе пропускаются.

Все операции одного исходного сообщения записываются одним пакетом. Ключ `message:<MsgID>` общий для всех анализаторов и хранится отдельно для каждого чата. Первый допустимый разбор сообщения считается окончательным; редактирование или последующий более полный разбор не добавляет новые операции к уже принятому пакету. Исправления вносятся через админку. Полностью одинаковые предложения AI в одном пакете объединяются; одинаковые суммы из разных исходных сообщений сохраняются как отдельные операции.

Остаток и запись журнала `chats/<chat>/debt_events/<hash>` сохраняются одной транзакцией Firestore. Карта `balances` заменяется целиком через маску `merge=[...]`, без сохранения удалённых вложенных ключей. Существующие встречные долги не взаимозачитываются автоматически. Переплата ограничивается существующим долгом и не создаёт обратный долг.

Журнал сохраняет исходные запрошенные операции и их порядок. Если дневной анализ находит более раннее сообщение, остаток восстанавливается от `journal_baseline` с учётом последующих возвратов, ручных установок и очисток. Обычная запись читает два документа; позднее событие дополнительно читает журнал чата. Стоимость такого восстановления растёт с длиной журнала; для больших архивов понадобится отдельная процедура контрольных снимков. Удалять журнал без такой процедуры нельзя: это нарушит защиту от повторов и восстановление порядка.

Админка отправляет UUID операции, повторно использует его после ошибки сети и блокирует одновременный повторный клик. API без `request_id` сохраняет совместимость; сторонние клиенты должны передавать UUID для защиты прибавлений и частичных погашений от повторов. Редактирование суммы сохраняет исходную пару участников.

## Переход с прежней версии

На старте приложения для существующих чатов текущие остатки сохраняются как исходный снимок, а `automatic_since` фиксирует время перехода. Исторические сообщения до этой границы автоматически не прибавляются к уже существующим суммам. Перезапуск не сдвигает границу. Новые события обрабатываются обычным порядком; текущие остатки при обновлении не обнуляются.

В старых остатках нет ссылок на сообщения. Поэтому накопленные ранее ошибочные дубли и разные псевдонимы одного человека нельзя достоверно исправить без сверки. До развёртывания стоит сохранить резервную копию Firestore; затем сверить спорные пары в админке. Не переименовывайте участников прямым редактированием документов: журнал содержит их прежние ключи. Автоматическое извлечение смысла сообщения по-прежнему зависит от AI; неоднозначные переводы, обещания и пересказы не должны попадать в журнал по правилам промпта.

## Проверка

`python -m pytest tests/test_debts.py tests/test_spontaneous_judgment.py tests/test_admin_cms.py -q`

`node tests/check_debts_ui.cjs`

Покрыты повторы и конкурентные обращения, отдельные равные операции, изоляция чатов, удаления, частичные возвраты и переплата, неверные суммы и участники, поздно обнаруженный долг, поздно обнаруженная переплата, ручные корректировки, переход со старых остатков и общий путь записи из разных анализаторов. Firestore изолирован тестовым хранилищем; отдельно проверяется protobuf-маска настоящего SDK. Проверка UI исполняет реальные функции отправки запросов в Node с подставным DOM/API.
